# Политика безопасности

## Как сообщить об уязвимости

**Не создавайте публичный Issue.** Используйте приватный канал GitHub:

1. Вкладка **Security** → **Report a vulnerability** (GitHub Security Advisories).
2. Опишите: версию/коммит, шаги воспроизведения, ожидаемое и фактическое поведение,
   оценку влияния.

Мы подтверждаем получение в течение 3 рабочих дней и сообщаем решение или план
в течение 10 рабочих дней.

## Что считается уязвимостью

- Обход аутентификации/авторизации, повышение привилегий, утечка ролей
- Инъекции (SQL, шаблоны), SSRF, path traversal, небезопасная десериализация
- Раскрытие секретов, токенов, персональных данных
- Подделка подписи/аудита, обход quality gates и Human Gate

## Что не считается

- Отсутствие заголовков безопасности на локальном dev-сервере
- Mock-адаптеры (Telegram/email/WhatsApp/Bitrix24), которые по замыслу локальные
- Известные ограничения, уже описанные в `README.md` (mock LLM-провайдер, отсутствие тестов бэкенда)

## Область действия

В области: код в `product/`. Вне области: `data/` (сырые исследования, в git не входят),
сторонние зависимости (сообщайте их авторам), тестовые литералы вроде `sk-test-…`.

## Секреты

В репозитории секретов нет и быть не должно: только `.env.example` с заглушками.
Если вы нашли в истории git реальный ключ — сообщите приватно, ключ будет отозван.

## Раскрытие

Публикуем advisory после выпуска исправления. Указываем автора находки, если он не против.
