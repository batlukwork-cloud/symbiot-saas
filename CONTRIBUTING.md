# Как участвовать

## Принципы

1. **Human Gate.** Изменения, затрагивающие production, секреты, живые интеграции,
   персональные данные и D1/readiness, не принимаются без явного решения правообладателя.
2. **Доказательства.** Каждое изменение поведения сопровождается проверкой:
   для графа диспетчера — `node test_executor.js` (ожидаемо 24 passed, 0 failed),
   для рантайма — proof-скрипт или сценарий приёмки.
3. **Секреты.** Никогда не коммитить ключи, токены, `.env`. Только `.env.example` с заглушками.

## Процесс

1. Форк → ветка `feat/<кратко>` или `fix/<кратко>`.
2. Коммиты с подписью DCO (см. ниже): `git commit -s`.
3. Pull Request: что меняется, зачем, как проверено (команды и вывод).
4. Ревью правообладателя. Слияние — только после прохождения проверок.

## DCO и права на вклад

Проект распространяется под AGPL-3.0-or-later **и** предлагается также по коммерческой
лицензии. Чтобы это было возможно юридически, вклад принимается на условиях:

1. **Developer Certificate of Origin 1.1** — подтверждается строкой в коммите:
   `Signed-off-by: Имя <email>` (даёт `git commit -s`).
2. **Уступка прав на релицензирование** — отправляя Pull Request, автор соглашается, что
   правообладатель вправе распространять принятый вклад также на условиях коммерческой
   лицензии. Автор сохраняет право указывать своё авторство.

Если вы не согласны с пунктом 2 — откройте Issue с предложением вместо Pull Request.

## Стиль кода

- Python: PEP 8, типизация, без новых зависимостей без обоснования.
- JS/TS: без сборщика там, где он не нужен; `node --check` обязателен.
- Документация: по-русски, с проверяемыми числами и ссылками на артефакты.

## Чего не принимаем

- Возврат вендорных рантаймов и `node_modules` в репозиторий
- Скриншоты и PDF вместо текстовых доказательств
- Правки, ломающие обратную совместимость контрактов API без ADR
