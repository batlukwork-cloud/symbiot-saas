# Симбиот: ручная приемка Windows Release Candidate

Статус документа: `D4_WORKDOC / manual acceptance checklist`.

Цель: проверить, что Симбиот запускается как Windows desktop GUI и работает как понятный пользовательский продукт, а Obsidian остается vault/connector.

## Перед проверкой

1. Распаковать release package в отдельную папку.
2. Убедиться, что установлен Node.js LTS.
3. Закрыть лишние старые окна Obsidian/connector, если они мешают проверке.

## Автопроверка

1. Запустить `RUN_SYMBIOT_RC_CHECK.cmd`.
2. Дождаться сообщения `Release Candidate check пройден`.
3. Проверить отчет в `runtime_logs`.

## Ручная проверка интерфейса

1. Запустить `START_SYMBIOT_DESKTOP.cmd`.
2. Убедиться, что открылось desktop-окно `Симбиот`.
3. Если появился fallback-экран запуска, нажать `Повторить` и проверить `runtime_logs\SYM_DESKTOP_BOOT_STATUS_2026-07-22.json`.
4. Слева должны быть инструменты: `LLM Hub`, `Контекст / RAG`, `Рабочие файлы`, `Evidence`, `Мобильный доступ`, `Windows Agent`, `Admin Sync`.
5. В центре должен быть чат и окно вывода.
6. Описать миссию обычными словами.
7. Нажать `Подготовить миссию` и проверить, что до LLM видны контракт, группа ролей, источники, бюджет, паспорт, Canvas/Graph и состояние approval.
8. Нажать `Запустить` и проверить живой ответ, файл результата, `Validator`, `Trace SHA` и следующий шаг.
9. Нажать `+ окно` до трех окон и затем `Сравнить LLM`.
10. Нажать верхнюю иконку результата и проверить правую preview-панель.
11. Переключить темную/светлую схему.
12. Проверить QR с телефона в той же локальной сети.

## Проверка Obsidian

1. Открыть Obsidian.
2. Включить community plugin `Symbiot`.
3. Нажать значок `Symbiot`.
4. Проверить connector.
5. Подключить vault.
6. Подготовить workspace.
7. Убедиться, что старые папки и заметки не удалены и не переименованы.

## Что считать приемкой

Приемка `PASS_WITH_CONDITIONS` допустима, если:

- desktop-окно открывается одной кнопкой;
- при проблеме запуска появляется понятный fallback-экран, а не пустое окно;
- в `runtime_logs` есть boot status запуска;
- connector отвечает;
- HARNES GUI отображается без сжатой Obsidian modal;
- три окна LLM доступны;
- QR появляется;
- Obsidian plugin видит connector;
- старый vault не поврежден;
- API-ключи не видны в интерфейсе и отчетах.
- полный контур миссии проходит `Gateway -> Router -> Role Registry -> Context Builder -> Role Runtime -> Validator -> Trace`;
- группа ролей содержит от 2 до 5 исполнителей и выбирается до первого вызова LLM;
- ответ без обязательных разделов не принимается Validator.

## Что не считать готовым рынку

- signed installer;
- публикация в marketplace;
- production remote relay;
- full Windows Agent без ограничений;
- tenant security audit;
- ручная приемка на нескольких клиентских машинах.
